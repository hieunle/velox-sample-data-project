# packaging-pg — Nordic Pack AB warehouse on PostgreSQL (synthetic)

The PostgreSQL twin of `../packaging-dwh` (same company, same 24 tables, same business rules and
tickets), built to exercise the Velox Databricks workflow with a **PostgreSQL source** and no tunnel:
**Assess** reads this folder, **Migration** reads the live copy through Lakehouse Federation. Nothing
here is real data.

The live copy is a Lakebase (Databricks-managed PostgreSQL 17) database `veloxpool`, generated by
`kms-healthcare/velox-databricks-app` `scripts/pg_packaging_data.py` — a translation of
`synapse_packaging_data.py` — at the demo size (`--max-rows 10000`, 158,709 rows). Its host is in
`config/connections.ini`; the password of `velox_reader` is never in this folder. The DDL in
`sources/code/ddl/` is generated by the same script (`--ddl`), so it matches the live copy exactly.

| Path | What it is |
| --- | --- |
| `sources/code/ddl/` | One file per table, 24 tables in `mfg`, `sales`, `supply`, `quality` |
| `sources/code/functions/`, `views/` | Four PL/pgSQL procedures and two views that carry the business rules (R-OEE-*, R-INV-*, R-CMP-1) |
| `sources/code/jobs/dwh_nightly.py` | The nightly load; reads `config/connections.ini` |
| `sources/docs/` | Functional spec with the rule table and open tickets, a DBA interview, kickoff notes |
| `sources/exports/` | Row counts and sizes from the live copy, 90 days of `pg_cron` history |

What differs from the SQL Server twin, because PostgreSQL differs: identifiers are lower case;
`datetimeoffset` is `timestamptz` (the plant offset is lost); `bit` is `boolean`; `money` is
`numeric(19,4)`; text is case-sensitive everywhere. The procedures and views exist only in this
folder, not in the live copy (they read `mes_eu` and `wms`, which the test copy does not have).
